## Recipe notes

Upstream vLLM (not ROCm fork). AITER integration comes from
PyTorch's third_party/aiter/ which has full gfx1151 support.

Build attempts AITER first (VLLM_ROCM_USE_AITER=1). If AITER
compilation fails, falls back to Triton-only build. Result is
recorded in .aiter-status file ("enabled" or "disabled").

## Scaffold notes

- There does not appear to be a current dedicated python-vllm-rocm AUR package; the closest package baseline is the generic AUR python-vllm package, with ROCm-specific integration coming from this recipe.
- Uses the latest stable upstream release tarball, currently v0.30.0, instead of a floating full Git clone.
- Carries a package-local CLI import patch so vllm --version remains a metadata-only path instead of importing optional OpenAI and Triton runtime modules at startup.
- Carries an optional-SageMaker patch so vllm --help and the base OpenAI server routes stay usable when model_hosting_container_standards is not installed.
- Carries a ROCm Triton unified-attention tile-size patch so large-head prefill paths such as Gemma 4 global attention do not request more than 64 KiB of LDS/shared memory on gfx1151.
- Carries a setup.py flag-forwarding patch so host CFLAGS/CXXFLAGS and HIPFLAGS are passed into the CMake ROCm extension build explicitly. This keeps Arch prefix-map sanitization and Strix tuning flags active in the shipped HIP extension modules.

## Intentional Divergences

- This package is ROCm-specific even though the closest Arch-family baseline is the generic aur/python-vllm package.
- Carries a deliberate Python-3.14 compatibility delta and recipe-specific ROCm integration that are not part of the generic baseline.
- Carries repo-owned Gemma 4 validation lanes for Strix Halo because the host-proven path is narrower than upstream defaults: text-only multimodal limits and per-checkpoint eager/compiled decisions. From vLLM 0.30.0 the lane runs on upstream TRITON_ATTN without AITER.
- Carries a repo-owned Qwen3.5 GDN patch lane (AMD-restricted FLA autotune grids and float32 gate exponents) for the parts of Blackcat Informatics' advisory recipe that are still missing from the maintained vLLM package source.
- Carries a repo-owned Qwen speculative-decoding patch lane for the padded EAGLE/MTP drafter batch Triton kernel on ROCm.
- Uses upstream vLLM DFlash model/runtime and speculators config parser support instead of carrying the former narrow parser backport locally.
- Builds one wheel without AITER. The build no longer exports VLLM_ROCM_USE_AITER or retries an AITER-less build, and the local carry no longer enables AITER on gfx1x; AITER is off the required gfx1151 path.
- Skips vLLM's optional Rust extensions, the `vllm-rs` frontend binary and `vllm._rust_tool_parser`, which upstream wheels ship. build() disables cargo and rustup toolchain installs so setuptools-rust reports both as failed optional extensions, and fails if the wheel contains either artifact. They back only the Rust frontend, the Rust tool parsers, and Rust bench paths.
- Carries a ROCm CK/direct FlashAttention interface gate that keeps the forced FLASH_ATTN probe blocked at backend selection until the imported flash_attn module exposes vLLM's paged-KV varlen API.
